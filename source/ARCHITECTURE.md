# 設計

ブラウザメモリのみで事例を保持。React UI → Worker → 原文単位のObservation → 23分類（複数可）→ 辞書・関連グラフ検索 → 任意のローカル埋め込み検索 → 5観点レビュー → 決定的優先度統合 → 確認質問・原文トレース。

公開ナレッジは独自作成の44確認視点。公式基本ケア44項目との対応が検証されたものではなく、公式項目番号として表示しない。検索ページでは確認済みの令和7年度改訂版（2026年3月31日）の章へリンクする。自動レビューの44視点と公式44項目は同一ではない。版・出典・権利を付けたKnowledge Packに差し替えられる。

ローカルAIはWebLLMをWorker内で実行。モデル出力は原文ID・項目IDの選択に限定し、未知ID・無根拠選択を拒否する。原文にない自由生成の疾病・家族・意向を画面の事実に混入させない。構文修復→再試行→ルール処理へ復帰。5視点は同一モデルの反復であり専門家5人の合意ではない。

通信: 初回モデル取得は固定の配布先へのGETだけ。推論入力はWorker内にとどまる。外部API、アクセス解析、ログ送信、事例の自動保存なし。モデルのみCache APIに保存。モデルの読込は設定で明示操作。中止はWorkerを終了し途中結果を破棄。JSON読込はサイズ・スキーマ・ID重複を検証。出力の再読込では結果を信用せず本文から再分析する。手動分類のみ、スキーマ検証と原文の位置・本文一致を条件に復元する。

確認優先度は診断・危険度ではない。未記載は一括不足判定せず、関連がある項目のみ追加確認の候補にする。否定・推量・伝聞・過去の検出は規則ベースの補助であり日本語を完全解析しない。分類信頼度は経験的目安で未較正。

分類は `classification-rules.json` の語句・正規表現と見出しを使う。過去の経過は02、支援利用は04、意向は07、交流は20、個別の留意点は23などへ複数分類する。23を無条件の受け皿にはせず、根拠の乏しい文章は未分類として手動整理を促す。

検索ページは独自の要点・質問、関連23項目、公式PDFの章ページを持つ。検索語は正規化と同義語展開を行う。表示テーマのみlocalStorageに保持し、事例データの自動保存は行わない。

更新確認は公開時のNode.js処理とブラウザ表示を分離。固定の公式URLを取得し、掲載リンクとPDFハッシュを比較する。ブラウザは同一配信元のupdates.jsonを検証して読む。失敗・未登録・変更・変更なし・結果の鮮度を区別。ソース更新は人が確認して基準を採用する。


v0.3：同一段落の直前2記載を用いる限定的な文脈規則を追加。既存の自由記述分類を意味理解モデルに置き換えたものではない。23項目の記録文は原文から決定的に整形し、利用者の編集をassessmentDraftsとして結果・保存JSONに保持する。編集文は根拠原文とは区別し、再分類で原文集合が変化したら警告する。公式基本ケアの階層データは独自レビュー項目と別ファイルで管理し、関連参照として結び付ける。

## 公式支援照合

`official-care-catalog.json` はR7本文の207支援の正本見出し・番号・階層・ページ。`official-care.ts` は独自の適用条件・質問・原文照合。従来の44質問パックと分離する。基本44／疾患別163を全件参照可能とし、関連記載だけの表示と全件表示を切り替える。疾患の期はユーザーが資料に沿って選択し、自動推定しない。家族の疾患や否定・疑いの記載を本人の診断根拠にしない。`clinical-context.ts` は過去／現在／否定の転倒記載から確認質問を調整する。
